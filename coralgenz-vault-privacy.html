ARCH 01

What is Zero-Knowledge Architecture?

💡
In Simple English:

In ordinary cloud services (like Google Drive or Dropbox), the company holds the master key to your files. In Coralgenz Vault, your computer or phone locks the file using AES-256 encryption BEFORE uploading. Our servers only receive scrambled digital gibberish. We physically cannot read what is inside.

The .secure format was invented and introduced by Coralgenz Global, and all rights are owned by the company. Conceived and engineered in Coimbatore, India, the .secure format eliminated the need to trust server administrators. The encryption and decryption happen exclusively in your browser’s volatile memory using the W3C Web Cryptography API. All container specifications, intellectual property, and proprietary algorithms are owned 100% by Coralgenz Global.

// Non-custodial mathematical proof:
Server_Receives = Encrypted_Ciphertext_Blob
Server_Keys = NONE (0 keys stored or transmitted)
Server_Ability_To_Decrypt = MATHEMATICALLY IMPOSSIBLE

Even if an attacker gains physical access to our database disks, all they get is random encrypted data that cannot be decrypted without your password.

ARCH 02

V10 16-Layer Cryptographic Pipeline & Mathematical Defense

💡
In Simple English:

Hackers use specialized supercomputers and GPU rigs to test millions of passwords every second. Coralgenz Vault enforces a 16-layer cryptographic gauntlet across 4 tiers inside your browser. By requiring 64 non-linear entropy rounds, a 512 KB memory barrier, 2,000,000 PBKDF2 iterations, S-Box bit diffusion, and post-quantum CRYSTALS-Kyber polynomial convolution, testing a single password candidate takes centuries instead of milliseconds.

The V10 specification implemented in Coralgenz Vault executes a 16-layer security model across 4 distinct tiers, combining key derivation mathematics, post-quantum lattice primitives, authenticated decryption, and in-browser enclave hardening. The .secure format was invented and introduced by Coralgenz Global, and all rights are owned by the company:

TIER 1 • L1–L3 Entropy & Memory Wall 64 Rds + 512KB Matrix
TIER 2 • L4–L6 Stretching & Diffusion 2M PBKDF2 + NIST S-Box
TIER 3 • L7–L9 Post-Quantum Lattice Kyber Lattice (q=3329)
TIER 4 • L10–L16 AEAD & Enclave Shield AES-GCM + zeroizeMemory
Tier 1 • Layers 1–3

Non-Linear Entropy Synthesis & Memory Walls

Eliminates short/simple password entropy shortfalls and establishes hardware memory barriers against GPU/ASIC rigs.

LAYER 01 expandPasswordEntropy

Non-Linear Entropy Expansion

Expands the user's password into a 64-byte array through 64 rounds of non-linear permutation, cyclic shifts, and mixing with four constants (C₁ = 0x9e3779b9, C₂ = 0x85ebca6b, C₃ = 0xc2b2ae35, C₄ = 0x27d4eb2f) alongside the container salt. This eliminates entropy shortfalls from short or simple passwords before hashing begins.

// Layer 1: 64 Rounds Non-Linear Entropy Synthesis
const expEntropy = expandPasswordEntropy(password, salt, [0x9e3779b9, 0x85ebca6b, 0xc2b2ae35, 0x27d4eb2f]);
LAYER 02 HMAC-SHA-512

Multi-Domain Pepper & Enclave Synthesis

Combines the Layer 1 expanded entropy with the decoded system pepper (SYS_PEPPER_V10) and format token (V10_FORMAT), feeding the combined byte stream into an HMAC-SHA-512 digest keyed by the container's 32-byte salt.

// Layer 2: Multi-Domain Pepper Fusion
const l2Stream = concat(expEntropy, SYS_PEPPER_V10, V10_FORMAT);
const l2Digest = await hmacSha512(salt32, l2Stream);
LAYER 03 computeMemoryHardMatrix

512 KB Memory-Hard Matrix Barrier

Argon2/scrypt-style sequential-memory barrier allocating an 8,192 × 64-byte state matrix (512 KB) derived from Layer 2. Sequential writing followed by pseudo-random index jumping ensures parallel ASIC and GPU brute-force crackers suffer severe latency penalties, finalized with HMAC-SHA-512 keyed with V10_L3 pepper.

// Layer 3: 512 KB RAM Matrix Computation
const matrix512KB = computeMemoryHardMatrix(l2Digest, 8192, 64);
const l3Digest = await hmacSha512(V10_L3, matrix512KB);
Tier 2 • Layers 4–6

Algorithmic Stretching & Galois Diffusion

Massive computational work factor, inverted salt bit avalanche, and Rijndael Galois Field non-linear confusion.

LAYER 04 PBKDF2-HMAC-SHA-256

High-Iteration Key Stretching (2,000,000 PBKDF2 Rounds)

Feeds Layer 3 output into 2,000,000 rounds of PBKDF2-HMAC-SHA-256 to produce a 512-bit intermediate pseudorandom string. Forces minimum ~100–300 ms client-side latency while imposing insurmountable computational overhead on mass offline parallel cracking.

// Layer 4: 2M PBKDF2 Key Stretching (512-bit output)
const l4Stream = await crypto.subtle.deriveBits({ name: "PBKDF2", salt, iterations: 2000000, hash: "SHA-256" }, l3Key, 512);
LAYER 05 salt[i] ^ 0xFF

Inverted Salt Avalanche Loop

Inverts every bit of the salt array (salt[i] ^ 0xFF), concatenates the result with the 512-bit PBKDF2 stream and V10_L5 pepper, and digests via HMAC-SHA-512. Any single-bit variance in password or salt cascades unpredictably across 100% of internal state bits.

// Layer 5: Inverted Salt Bit Avalanche
const invertedSalt = salt.map(b => b ^ 0xFF);
const l5Digest = await hmacSha512(V10_L5, concat(invertedSalt, l4Stream));
LAYER 06 NIST FIPS 197 S-Box

NIST FIPS 197 Rijndael S-Box Diffusion

Passes Layer 5 bytes through the AES Galois Field GF(2⁸) multiplicative inverse Substitution Box (S-Box) combined with container salt bytes, destroying all linear and algebraic correlations, and signed with HMAC-SHA-512 keyed by V10_L6.

// Layer 6: GF(2⁸) Rijndael S-Box Non-Linear Transformation
const sboxOutput = applyRijndaelSBox(l5Digest, salt);
const l6Digest = await hmacSha512(V10_L6, sboxOutput);
Tier 3 • Layers 7–9

Post-Quantum Lattice & Key Extraction

ML-KEM / CRYSTALS-Kyber ring polynomial convolution, non-linear feedback mesh, and CSPRNG nonce fusion.

LAYER 07 polyMulNegacyclic (q=3329)

ML-KEM / CRYSTALS-Kyber Lattice Ring Polynomial Diffusion

Maps Layer 6 bytes and container salt into two 256-degree polynomials modulo q = 3329 (FIPS 203 / CRYSTALS-Kyber standard) and computes negacyclic convolution in the polynomial ring ℤ₃₃₂₉[X] / (X²⁵⁶ + 1). Infuses the key derivation chain with post-quantum Learning With Errors (LWE) lattice hardness.

// Layer 7: ML-KEM / CRYSTALS-Kyber Ring Polynomial Convolution
const polyA = initPolyFromDigest(l6Digest, 256, 3329);
const polyB = initPolyFromSalt(salt, 256, 3329);
const latticeProduct = polyMulNegacyclic(polyA, polyB, 3329);
LAYER 08 HMAC-SHA-512

Secondary Non-Linear Feedback Mesh

Compresses the 256-coefficient polynomial back into a 64-byte digest using non-linear fold mixing, bound with V10_L8 pepper, and signed via HMAC-SHA-512 keyed by the lattice output bytes.

// Layer 8: Lattice Mesh Folding & Pepper Signing
const foldedLattice = foldLatticeCoefficients(latticeProduct);
const l8Digest = await hmacSha512(foldedLattice, concat(V10_L8, l6Digest));
LAYER 09 256-Bit Raw Master Key

Context Domain & CSPRNG Nonce Fusion

Binds Layer 8 digest with container salt and domain pepper V10_L9 via HMAC-SHA-512, then extracts the primary 32 bytes (256 bits) as the raw AES master key. The raw bytes remain strictly unexportable in memory.

// Layer 9: Extraction of 256-Bit Raw Master Key
const l9Digest = await hmacSha512(salt32, concat(l8Digest, V10_L9));
const rawAesKey = l9Digest.slice(0, 32); // 256 bits
Tier 4 • Layers 10–16

Authenticated Framing, Verification & Enclave Defense

Non-extractable WebCrypto key, AAD header binding, AES-256-GCM AEAD, format guardrails, prototype freeze, and ephemeral RAM scrubbing.

LAYER 10 extractable: false

AES-256-GCM Key Framing

Imports the 256-bit raw key into the browser's hardware-backed WebCrypto engine as an unexportable handle (extractable: false), preventing client-side malicious scripts or third-party extensions from reading the key.

const cryptoKey = await crypto.subtle.importKey("raw", rawAesKey, "AES-GCM", false, ["decrypt"]);
LAYER 11 additionalData (AAD)

Additional Authenticated Data (AAD) Header Binding

Preamble, format token, encryption version, and JSON container metadata are encoded as Additional Authenticated Data (AAD) within the AES-GCM cipher engine. If an attacker modifies even a single metadata byte, decryption fails immediately.

const aadBytes = new TextEncoder().encode(JSON.stringify({ ver: "V10", fmt: ".secure", salt, iv }));
LAYER 12 AES-GCM 128-bit Tag

Galois/Counter Mode (GCM) Authenticated Decryption

Executes authenticated symmetric decryption over the ciphertext stream with a 96-bit CSPRNG IV and verifies the 128-bit authentication tag. Ciphertext tampering throws an instantaneous hardware DOMException abort.

const plaintextBuffer = await crypto.subtle.decrypt({ name: "AES-GCM", iv, additionalData: aadBytes }, cryptoKey, ciphertext);
LAYER 13 INTEGRITY_HASH

Post-Decryption SHA-256 Integrity Verification

Computes an independent SHA-256 cryptographic digest of the recovered plaintext and strictly compares it against the container's signed INTEGRITY_HASH, confirming byte-for-byte fidelity.

const computedHash = await crypto.subtle.digest("SHA-256", plaintextBuffer);
if (!timingSafeEqual(computedHash, expectedHash)) throw new Error("Tampered Payload");
LAYER 14 verifyFormatIntegrity

Format Integrity Barrier

Enforces mandatory .secure extension and binary signature validation. If renamed to .html or stripped of headers, the file automatically locks and refuses to execute in the browser.

function verifyFormatIntegrity(file) { if (!file.name.endsWith('.secure')) throw new Error("Invalid format"); }
LAYER 15 Runtime Shield

Runtime Enclave & Anti-Tampering Shield

Freezes JavaScript prototypes (Object.freeze(Object.prototype), Array.prototype, Uint8Array.prototype, crypto.subtle), activates DevTools debugger traps, disables context menus, and renders a blur shield when focus shifts away from the viewer.

[Object, Array, Uint8Array].forEach(p => Object.freeze(p.prototype)); Object.freeze(window.crypto.subtle);
LAYER 16 zeroizeMemory()

Ephemeral Zeroization & RAM Scrubbing

All key buffers, intermediate arrays, and plaintext objects are actively overwritten with zeroes (.fill(0)), blob URLs are immediately revoked, and DOM elements are wiped from memory on session lock, tab switch, pagehide, or window unload.

function zeroizeMemory() { rawAesKey.fill(0); expEntropy.fill(0); URL.revokeObjectURL(blobUrl); }
  • Post-Quantum & Pre-Hash Protection: Combines 64-round non-linear entropy expansion with ML-KEM / CRYSTALS-Kyber ring polynomial diffusion (q=3329) to thwart quantum and classical supercomputer threats.
  • Double-Integrity Guarantee: Both AES-256-GCM 128-bit authentication tags (Layer 12) and post-decryption SHA-256 digest validation (Layer 13) guarantee tamper-proof file recovery.
  • Ephemeral In-Memory Lifecycle: Keys and cleartext never touch disk or network; all buffers are wiped via zeroizeMemory() immediately after session termination.

ARCH 04

RAM Scrubbing (zeroizeMemory Protocol)

💡
In Simple English:

Other websites leave opened files sitting in your computer's memory even after you switch tabs. Coralgenz Vault immediately overwrites memory with zeroes (.fill(0)) as soon as you close the file, so spyware cannot read it.

Our automated memory zeroization protocol wipes unencrypted bytes from browser RAM:

  • Immediate Overwrite: The unencrypted byte buffer is immediately overwritten with binary zeros (.fill(0)) before garbage collection triggers.
  • Automated Triggers: Executes when you lock the vault, close the browser tab, minimize the window, or when an idle timer expires.
  • Screen Guard Protection: If you switch away from the window or press screenshot keys, the container view is instantly blurred to prevent visual shoulder-surfing.
